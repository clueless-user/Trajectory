## 1. What changed today

### Commit `39b506f` — chore: verify native tauri environment

- **Fixed the hard build blocker**: `src-tauri/` had no `icons/icon.ico`, which hard-fails the first Windows compile of any Tauri 2 app. Generated a 1024×1024 source icon (dark rounded square, cyan rising trajectory with milestone notches) programmatically and ran `pnpm tauri icon` to produce the full desktop icon set (`icon.ico`, `icon.icns`, PNG sizes, Windows Store logos). Mobile (iOS/Android) icon sets were deleted — desktop-only.
- **Enabled bundling**: added a `bundle` section to `src-tauri/tauri.conf.json` (`active: true`, `targets: ["nsis"]`, icon list) so the production build path targets a real Windows installer, not just a bare exe.
- **Committed `src-tauri/Cargo.lock`** (generated by the first compile; an application should pin its Rust dependency graph).
- **Removed the disposable-database trap** in `src/repositories/database.ts`: `initializeDatabase()` used to silently fall back to in-memory sql.js if the Tauri SQL plugin failed — inside the native app that means *every change evaporates on exit with no warning*. Now, inside Tauri, a native DB failure **throws**. Browser dev/test keep the in-memory fallback (correct there).
- **Boot error surface** in `src/App.tsx`: a DB failure now renders an explicit "DATABASE FAILURE" screen with the error message instead of spinning on "INITIALIZING TRAJECTORY ENGINE…" forever.
- **Migration runner version check**: `runMigrations` now reads `_migrations` first and skips migration 001 when version 1 is already recorded (the bookkeeping table is created before the check, so fresh databases still work). All DDL remains idempotent `IF NOT EXISTS`. Migration 001 content itself was not touched.

### Commit `73796c5` — feat: persist deep work sessions for crash safety

- `useSessionStore.startSession` now **writes the `work_sessions` row immediately** with `completed_state: 'paused'`. Previously a session lived only in Zustand memory: an app crash lost the entire record. Now a crash leaves a truthful row.
- `finishSession` **updates that same row** to `'finished'` with real `end_time`, `duration_seconds`, interruption count, and notes (previously it inserted a new row; now the paused placeholder is promoted). `start_time`/`end_time` are wall-clock brackets; `duration_seconds` counts only running time (paused gaps excluded).
- `cancelSession` **deletes the row** — cancellation means the session never happened, so no orphaned placeholder is left.
- Added **injectable clock** (`setNowForTesting`) so tests can control time without real waiting.
- `startSession` is now async (it does a DB write) and guarded against double-start; `TodayView` awaits it before switching to the Deep Work view so the cockpit never flashes the empty state.

### Commit `7cffbbb` — fix: compute habit consistency from real log history

- `HabitsView` was feeding `calculateRollingConsistency` a **hardcoded sample array** — every habit showed a fake trajectory label. It now calls the new `HabitRepository.getRecentStatuses(habitId, endDate, days)`, which returns per-day statuses over the last 7 days where **an unlogged day counts as missed** (`none`), and renders the label from that real history (tooltip shows the normal/minimum/missed counts).

### Commit `871fc7c` — docs: preserve MVP walkthrough baseline

- The original Day-0 MVP walkthrough committed as-is before being superseded by this file (its one known inaccuracy: it claimed the migration runner reads `001_initial_schema.sql`; it actually uses an inline copy in `database.ts` — the `.sql` file is reference documentation).

## 3. What is NOT working / NOT yet verified (honest list)

1. **Native persistence lifecycle is unverified.** The native window launched, but the critical loop — *launch → create data → close → relaunch → data still there* — has not been executed yet. Unit tests against in-memory sql.js are **not** proof.
2. **Database file location undocumented.** `sqlite:trajectory.db` is resolved by tauri-plugin-sql at runtime (expected: the Windows app config dir, e.g. `%APPDATA%\com.trajectory.app\trajectory.db`), but the real path has not been confirmed on disk.
3. **`pnpm tauri build` has never run.** Bundle config (NSIS) is in place; first build will download NSIS and produce the installer. Unverified either way.
4. **Critical-path test matrix is not strengthened yet.** Still missing (per the phase spec):
   - Compression: empty day, under/mild/severe overload, critical-over-budget, optional strict-fit, equal-priority tie-breaks, repeated-compression determinism, no-task-created/deleted invariant, deferred-task recoverability.
   - Sessions: full pause/resume/multi-cycle lifecycle against the DB, immediate finish, interruption note format, cancel-persists-nothing, actual_minutes accumulation, clock-controlled timing.
   - Habits: consistency edge cases (empty window, all-missed, >window clamp), historical edits, `getRecentStatuses` itself.
   - Rabbit holes: **zero tests** (capture-during-session integrity, provenance, conversion).
   - Brain dump: **zero tests** (verbatim raw-text preservation, upsert, promote-to-task).
   - Today screen: only a static-label smoke test; no behavioral coverage (sections, workload, completion, compression visibility).
   - Repository CRUD for work sessions / rabbit holes / brain dumps: untested.
5. **Seed data doesn't exist yet.** Only the default 4 areas + 4 habits. No deterministic dev dataset (goals/projects/tasks/logs/sessions/states/reviews/rabbit holes/brain dump).
6. **"Use the product as a user" exercise hasn't happened.** No real morning / deep work / overload / evening workflow has been run in the native app.
7. **Docs are stale.** `ARCHITECTURE.md` (claims React 19, wrong migrations path, a false "30-second flush" claim — now superseded by the real crash-safety design), `DATA_MODEL.md` (missing persistence semantics + seed strategy), `ROADMAP.md` (no Phase 1.5 section; stale Milestone 01 checkboxes).
8. **Known product limitations discovered (deliberately deferred, need decisions/work):**
   - An orphaned crash-safety row (`completed_state: 'paused'`) is written but there is **no recovery UI** — on relaunch the user isn't told the previous session was interrupted.
   - **Inbox tasks are invisible**: `NewTaskModal` without "Schedule for Today" creates an `inbox` task that no view renders.
   - `ReviewView`'s "tomorrow objective" is saved to the review but **never surfaced the next morning** (primary objective stays store-memory only).
   - The session timer only ticks while `DeepWorkView` is mounted; navigating away pauses elapsed-time accumulation silently.
   - `daily_states` has no unique constraint on `date` (upsert is lookup-based).
   - Zod schemas exist but are never used for runtime validation at repository boundaries.
9. **No git remote is configured.** Everything is committed locally on `main`; pushing requires the user to add a remote (per phase rules: no remote setup without explicit request).
